If you are hosting Cloudy for a specific group of people, you can enable password protection to control who can access your instance. Cloudy uses **HTTP Basic Authentication**, which prompts visitors with a browser-native login dialog before they can view any page.

<Note>
  Password protection is only available for **self-hosted** Cloudy deployments. It has no effect on managed or shared instances where you do not control the server.
</Note>

---

## Enabling Password Protection

<Steps>
  <Step title="Open config.js">
    In the root of your Cloudy installation, open `config.js`. By default it looks like this:

    ```javascript config.js
    const config = {
      challenge: false, // Set to true if you want to enable password protection.
      users: {
        // You can add multiple users by doing username: 'password'.
        interstellar: "password",
      },
    };

    export default config;
    ```
  </Step>

  <Step title="Enable the challenge">
    Change `challenge: false` to `challenge: true` to turn on password protection.
  </Step>

  <Step title="Add your users">
    Inside the `users` object, add one entry per user in the format `username: "password"`. Remove or replace the default `interstellar` entry.
  </Step>

  <Step title="Start the server with the config flag">
    Launch Cloudy with the `config` environment variable set to `true` so the server loads your `config.js` settings.

    <CodeGroup>
      ```bash pnpm (Linux / Mac)
      config=true pnpm start
      ```

      ```powershell pnpm (Windows)
      $env:config=true; pnpm start
      ```

      ```bash npm (Linux / Mac)
      config=true npm start
      ```

      ```powershell npm (Windows)
      $env:config=true; npm start
      ```

      ```bash bun (Linux / Mac)
      config=true bun start
      ```

      ```powershell bun (Windows)
      $env:config=true; bun start
      ```
    </CodeGroup>
  </Step>
</Steps>

---

## Adding Multiple Users

You can add as many users as you need by listing them in the `users` object, one per line:

```javascript config.js
const config = {
  challenge: true,
  users: {
    alice: "password123",
    bob: "securepass",
  },
};

export default config;
```

Each key is the username and its value is the corresponding password. All users share the same level of access — there are no roles or permissions beyond the login challenge.

---

## How It Works

When `challenge` is set to `true` and the server is started with `config=true`, Cloudy intercepts every incoming request before serving any content:

1. The visitor's browser displays a **native login dialog** asking for a username and password.
2. If the credentials match an entry in the `users` object, the request proceeds and the page is served normally.
3. If the credentials do not match, the browser shows the login dialog again.

<Warning>
  HTTP Basic Authentication transmits credentials encoded in **Base64**, which is not encryption. Anyone who can intercept the network traffic can decode the credentials. Always serve your Cloudy instance over **HTTPS** in production to protect your users' passwords.
</Warning>
